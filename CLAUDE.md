# Studio Yukon retainer portal

Netlify site where each retainer client logs in with their email and sees their own dashboard. Jordy asks Claude to update it. Pushing to `main` deploys in about a minute.

## Where things live

- `public/data/<slug>.json`: one file per client. Budget (deposits), rate, projects, hour entries, theme colours. The client's browser loads this file, so nothing private goes in it.
- `config/users.json`: client logins (email, name, notify flag). People log in with a link sent to their address, so there are normally no passwords. Never shown to clients. Admins are not here; they live in the `PORTAL_ADMINS` env var on Netlify.
- `public/assets/retainer.js`: the only place budget maths happens. Dashboard, alerts and the CLI all import it.
- `public/assets/clients/<slug>.svg`: client logos. Use `fill="currentColor"` and a viewBox so the logo follows light and dark mode.
- `netlify/functions/retainer-alerts.mjs`: hourly. Emails client contacts once at 50%, 20% and 10% remaining.

## Rules

- Change data only through `node scripts/portal.mjs`. It validates, assigns entry ids, stamps `updated` and prints the new balance. Run `node scripts/portal.mjs help` for every command.
- Never edit `config/users.json` by hand and never commit a plain-text password. `user:add` needs no password: the email address is the key. `user:password` exists only as a rare fallback.
- `public/assets/clients/<slug>.json` is generated by the script (logo and colours for the branded login). Don't edit it; change the theme with `client:set`.
- Run `node scripts/portal.mjs validate` before every commit. Do not push if it fails.
- Every push is a Netlify production deploy (15 of 300 free credits a month). Bundle all changes into one push. Never push more than once a day; if Jordy asks for a second update the same day, commit locally and say it goes live with the next push, unless he says it is urgent. Aim for 4 to 8 deploys a month.
- Log notes are read by the client. Write them in Dutch, short and factual ("Uitwerking key visual", "Correcties na feedbackronde"). No em dashes. No sentence that tacks a clause on with a comma plus "en" or "maar".
- Commit message: `<client>: <what changed>`, e.g. `vandebron: 2 u social templates (e23)`.
- Example clients (`"example": true`) never trigger emails. `client:live <slug> --reset` turns an example client into a real one (clears example hours and deposits).
- Slugs are the URL (`/vandebron/`). Lowercase, hyphens only. `admin`, `login`, `logout`, `api`, `data` and `assets` are reserved.

## Logging from Jordy's notes (the normal way)

Jordy keeps one loose text file with notes about everything. When he says "verwerk mijn notities" (or pastes them):
1. Pick out only lines about retainer clients, with hours or an amount. Skip everything else silently.
2. Turn each into `{ date, hours | kind:"cost"+amount, note, projectName?, src }`. `src` is the original note line, word for word. It is what prevents double logging.
3. Note: short Dutch description for the client ("Banners laadpas campagne"), not Jordy's shorthand.
4. projectName: reuse an existing project name when the work clearly belongs to it (`show <client>`), otherwise a short new name. Leave it out for small one-off work: it then goes to Ad hoc.
5. Dates: resolve "ma", "gisteren", "3/3" against today. If a line has no usable date, use the date of the note block it sits in, or ask.
6. Write the lines to a temp file, run `import <client> --file x.json --dry-run`, show Jordy the list, then run it for real after his OK.
7. A line without hours ("bellen met Robin") is not logged. Mention lines you were unsure about, in one short list.
8. Logging hours on a project marked Opgeleverd? Set it back to Lopend with `project:set`.

## Common requests

| Jordy says | Run |
|---|---|
| "2 uur op social templates voor Vandebron" | `log vandebron --project social --hours 2 --note "..."` (or `--project-name "..."`; no project means Ad hoc) |
| "nieuw project laadpas campagne" | `project:add vandebron --name "Laadpas campagne"` |
| "die regel van gisteren was 3 uur" | `show vandebron` to find the id, then `entry:edit vandebron e23 --hours 3` |
| "stocklicentie van 120 euro voor slim laden" | `cost vandebron --amount 120 --note "Stocklicentie illustratie" --project slim-laden` |
| "zet in de afspraken dat animatie er niet onder valt" | `scope vandebron` to see the current lists, then `scope vandebron --out "Item | Item | ..."` with the full new list |
| "ze hebben 3000 bijgestort" | `deposit vandebron --amount 3000 --label "Aanvulling"` |
| "geef Jasmijn ook toegang" | `user:add vandebron --email ... --name "..."`. It refuses a domain that belongs to another client, and asks for `--other-domain` when the domain differs from the client's other logins. Never add that flag without Jordy confirming the person works for that client |
| "nieuwe klant Acme" | `client:new acme --name "Acme" --rate 110 --start ... --end ... --deposit ...` then logo, `user:add`, `client:live` |
| "Acme's hoofdkleur is #FFD400" | `client:new ... --brand "#FFD400"` (or `client:set acme --palette "#FFD400"` later). The script derives all theme colours and prints any contrast shift; tell Jordy about those shifts |

After pushing, report the new remaining budget and say if a 50/20/10 line was crossed, because that client gets an email within the hour.
